# Lean CI: tiers and one consolidated whole game

**Owner:** WS4 (ci.yml and the e2e harness). **Ruling:** the PM's lean-CI ruling in `.handover/SEAMS.md`, 2026-10-28,
from Heiko: "keep ci tests as efficient as possible … not all tests that we used to implement a feature should go into
ci". **Status: done.** Part 1 (tiers, flags, the hold) merged as #92 (3f4ab4d); part 2 (the folds) merged as #108
(84527f7), each with its before and after CI seconds. Open, WS6's: the shell and chat folds; shell.ts stays in
`e2e:regression` until then.

## The rules this implements (SEAMS, quoted in short)

1. CI is the regression gate, not implementation scaffolding: a CI test guards a player-facing promise (B-AC, UBER-AC)
   or a real past bug (FM), and no cheaper test covers it.
2. Tier 1, every PR (lane sub-PRs too): typecheck, unit tests, ONE pinned-seed whole-game e2e. Under 4 min wall.
3. Tier 2, only PRs into feat/strategist or main: the rest of the regression e2e and the sim smoke. Under 8 min wall.
4. Tier 3, local only: render gates, mutation sweeps, probes, timing, three-set sims, feature-building e2e.
5. A new feature adds a unit test or a STEP in the existing whole game, not a new e2e file, unless no game can reach it.
6. No wall-clock assertions in CI.

## Phase A — tiers (done, c912e04 and after)

- `check` (Tier 1): typecheck, unit tests. `e2e` (Tier 1): build, `e2e:core` = smoke on `MULE_E2E_SEED=1`, with WS3's
  auction hooks inside it. The random-seed duplicate of the whole game is gone.
- `sim` (Tier 2): 4 games, every persona in every seat once (WS1). `e2e-regression` (Tier 2): `e2e:regression`.
- Local-only unit tests, whole files or sweeps inside one, run only with `MULE_FULL=1`
  (`describe.runIf(process.env.MULE_FULL === '1')`, or a sample size switched on it); `pnpm test:full` runs them.
- Tier 2 unit tests (each plays whole games) run only with `MULE_TIER2=1` or `MULE_FULL=1`; `pnpm test` skips them and
  the `sim` job runs them by file (94a6dde, WS3's T-AC-7 first).

## Phase B — one whole game hosts the steps

### Why the steps left the game, and the fix

chat.ts, shell.ts and specials.ts run their own games because their steps raced smoke's clock: at phaseScale 0.1,
planning lasts 4.5 s, and a step that looks around for longer loses the phase under it. Each own game costs a server,
browsers, a lobby and a month: chat.ts alone is 105 s in CI.

**The hold.** `Room.hold()` / `Room.release()` (packages/tabletop, test-only in use, WS4) and a harness helper
`held(server, code, step)` (apps/web/e2e/harness.ts, WS4). While a room is held, every callback the game scheduled
that comes due waits: phase ends, the grant's light, AI turns, auction ticks. The real clock keeps running and messages
are still handled, so a screen can act and every screen still hears views. On release the waiting callbacks run in the
order they came due. Nothing about time changes, only when callbacks fire, so the game's own logic is untouched.
A step that needs time to pass (the grant's light moving, an AI line arriving) runs unheld.
The server reaches a room with `server.registry.get(code)`, as store-steps.ts already does: no server edit.

**What a hold does not hold** (measured in the hold's review, 2026-10-28):
- **A player's development turn runs on real time.** `devEndsAt` is set from `now()` (mule-game.ts:432). Once it passes, `requireTime` refuses buy, outfit, install, analyse, filter and the pub, and `doneDeveloping` counts the player done; Develop.tsx swaps the store and map for "Time is up". At phaseScale 0.1 the phone's turn is 5 s.
- **A screen's own message can still end a phase while held:** Ready, the last claim, a phone dropping (`checkAllReady`).
- **The production show plays out on real time,** but stays usable ("On to the auction").
- **Header timers** show 0 and pulse amber under a hold; they are display only and disable nothing.

So a step that needs the phone's own development turn (the store, the development map) runs **unheld and inside that turn**, after the store steps; whatever doesn't fit stays in its Tier 2 game. A longer test-only development turn was rejected: the AI hands play development at a human's pace until the pub, so a longer turn makes every AI do more, slows the game and changes seed 1's game. Steps that only look at the TV, or use the header (chat, the move button), may be held in development.
