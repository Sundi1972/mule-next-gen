M.U.L.E. Next Gen rulebook

How the game works today, rule by rule and number by number, and what is designed, being built or still open. It is both our rulebook and our design book.

How to read this book In the game

Each chapter follows one part of a month at the table. Every topic starts with how it works in the game today, in plain words, with its real numbers. Where a rule is about to change, a box says what is changing, who decided it and who is building it.

Each topic carries one label, so you can see at a glance how settled it is:

In the game on the main build today Being built a change is in a pull request Designed ruled or approved, not built yet Being designed a design or a question is open Backlog wanted, nobody on it yet

Search finds any word in any chapter: type in the box at the top, or press /. Press Enter to jump to the first result.

Where the facts come from In the game

The game's code on the main build is the source of truth. Every number in this book is the value in the game's settings file, and the Every number page is generated from that file, so it can't drift. Rulings and their reasons come from the programme's decision log: what Heiko decided, and what the programme manager ruled under his authority, each with its date.

Where this book and the game disagree, the game is right and the book has a bug. Tell the programme manager.

How the book stays current In the game

The rule for every team: a pull request that changes a rule, a number, a screen or a behaviour updates the chapter that describes it, in the same pull request. When the change merges, its "Being built" label becomes "In the game". A new design gets its own section the day its goals are agreed. The programme manager publishes the book again after every batch that reaches the main build.

Kept current by: the programme manager. How to write a section: docs/rulebook/WRITING.md.
