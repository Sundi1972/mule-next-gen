## §0 · Business Goals & Value

### G-1 · Months that differ `[handoff]`

A production event sometimes gives a bonus or a setback to all plots, to one area, or to single plots, seeded and
replayable.

- **Who benefits** `[review-only]`: the family at the table and the TV room, who see something happen to the colony they
  can react to and talk about; and the AI seats, which must cope with it.
- **Today** `[review-only]`: no event system. `verified_by: read` — the only mention in `packages/engine/src` is a config
  comment that some plot traits "only change event risks". Every month runs the same rules; a game's story comes only
  from prices.
- **Value** `[review-only]`: variety and stakes from month to month (the original's best-remembered feature), real supply
  shocks that make storing and spreading out matter, and data the screens (WS6) can badge and animate per plot.
- **UBER-AC-1:** on `pnpm sim -- --games 40 --seed 101`, events fire in 30-60% of months, every game sees at least 3
  different events, and no balance check that printed ok on the same maps before events prints MISS after.
- **UBER-AC-2:** every month report carries the events that fired, with the plots each hit and the per-plot production
  line (§3); replaying the same seed gives the same events.

**Non-goals** `[review-only]`: hedges (insurance, silos, levees, observatory), warnings ahead of time (`warnings[]` ships
empty), chains, council votes, market and price events, MULE destruction and tile changes, personal cash events. Each
could be its own spec later.

**Rough cost** `[review-only]`: about 2-3 days for the 10 events and the report contract; the thin version (4 colony-wide
events, no per-plot lines) about 1 day.

## §0.1 · Decision Record `[review-only]`

- **Chosen:** 10 production events of four shapes (colony, local, spreading, single plot) and the full report contract.
  About 2-3 days.
- **Thin baseline:** 4 colony-wide events and no per-plot lines. About 1 day. **Loses because** Heiko wants events
  animated on the map ("cool visual representation on the screen (map), nice animations", via the PM 2026-10-21), and a
  colony-wide event without per-plot hits and an origin gives WS6 nothing to draw.
- **Larger:** a deck of ~25 of the catalogue's 40, warnings, hedges, chains. Later specs, each on its own value.

## §2 · The Logic `[handoff]`

```
RULE-1 · Does an event fire this month, and which                shape: decision table

inputs
  whatIf      true | false          C5's flag; absent means false
  month       integer ≥ 1
  last        event key | none      the event in last month's report
  roll        [0, 1)                rng(seed, month).next()
  eligible    set of event keys     keys whose RULE-2 targets are non-empty this month
first match wins
  #  when                                 then
  1  whatIf                               no event
  2  month < EVENTS.firstMonth (2)        no event
  3  roll ≥ EVENTS.chance (0.5)           no event
  4  eligible minus {last} is empty       no event
  5  otherwise                            one key from eligible minus {last}, by EVENTS weight
unknown
  last = none (month 1, or no event last month): nothing is excluded.
examples
  month 1 -> none · roll 0.7 at chance 0.5 -> none · last = drought, roll 0.2 -> anything eligible but drought
```

```
RULE-2 · What an event hits                                     shape: decision table by key

event          kind      scope     sign  targets (working plots, owner set)                origin / direction / order
dustStorm      storm     colony    bad   every Energy plot                                  seeded edge; order by distance from it
drought        drought   colony    bad   every Food and Water plot                          seeded edge; as above
acidRain       storm     colony    bad   every Energy and Food plot                         seeded edge; as above
solarFlare     flare     colony    good  every Energy plot                                  seeded edge; as above
cometPass      comet     colony    good  every Water plot                                   seeded edge; as above
flood          flood     local     bad   Food plots on river tiles                          a seeded river tile; order by distance
volcanicAsh    quake     local     bad   raw plots within EVENTS.volcanicAsh.radius (2)     a seeded volcanic or mountain tile
                                         of the origin                                      (owned or not); order by distance
pestSwarm      blight    personal  bad   a start Food plot, then adjacent Food plots          the start plot; order = spread order
                                         (any owner), breadth first, up to maxPlots (4)
wildfire       fire      personal  bad   a start Food plot, then the rest of its owner's       the start plot; order = spread order
                                         Food cluster
bumperHarvest  bounty    personal  good  one working raw plot                                the plot; order 0

start plot (pestSwarm, wildfire, bumperHarvest): with probability EVENTS.targetBias (0.5) drawn
from the leader's eligible plots (bad) or the trailing player's (good); otherwise from all
eligible plots. Leader and trailer by money + GAME.plotScore × plots owned.
player: the start plot's owner, for personal events; absent otherwise.
unknown
  no eligible plot for a key -> the key is not eligible (RULE-1 #4/#5).
  a tie for leader or trailer -> the first in seat order.
```

```
RULE-3 · How much each hit plot changes                         shape: formula by key

applied after every other part of the plot's output (RULE-4), floored so made ≥ 0
  dustStorm      Energy: made × (1 − EVENTS.dustStorm.cut 0.5), rounded down
  drought        Food, Water: −EVENTS.drought.loss (1)
  acidRain       Energy, Food: −EVENTS.acidRain.loss (1)
  solarFlare     Energy: +EVENTS.solarFlare.gain (2)
  cometPass      Water: +EVENTS.cometPass.gain (2)
  flood          Food: made → 0
  volcanicAsh    any raw good: −EVENTS.volcanicAsh.loss (1)
  pestSwarm      Food: made × (1 − EVENTS.pestSwarm.cut 0.5), rounded down
  wildfire       start plot: made → 0; the rest of its cluster: −EVENTS.wildfire.loss (1)
  bumperHarvest  its good: made × EVENTS.bumperHarvest.factor (2)
delta = made after − made before; a plot whose delta is 0 (already 0) is still listed as hit.
examples                                                     -> become AC cases in §6
  Energy plot making 5 in a dust storm -> 2 (delta −3)
  Food plot making 1 in a drought -> 0 (delta −1); making 0 -> 0 (delta 0, still listed)
  Water plot making 3 in a comet pass -> 5 (delta +2)
```

```
RULE-4 · A plot's production line                               shape: formula

parts, in this order, each {why, delta}:
  ground    the ground rating's base (mined: tile.ground[good]; grown: max(GROWN_MIN, GROWN_BASE + ground))
  trait     each trait's TRAIT_EFFECT, and a thin vein's loss
  species   Mollox mine, Bramblet farm
  cluster   the adjacency bonus (only when output > 0, as today)
  pollution −the pollution loss
  floor     the correction that keeps the sum ≥ 0 (as today's Math.max)
  noEnergy  −the half lost for missing Energy
  noWater   −the half lost on a farm whose owner is short of Water
  event     the RULE-3 delta, with the event key
factories: one part {why: 'factory', delta: fit.output} (the fit lines already explain it),
  or nothing if it couldn't run.
invariant: sum of parts = made = what was credited to the owner.
```

## §3 · Contracts & Data Models `[handoff]`

**MonthReport additions (ADDED, non-breaking; producer C2/C4, consumers WS6 screens, later WS3 protocol)**

```ts
type EventKey = 'dustStorm' | 'drought' | 'acidRain' | 'solarFlare' | 'cometPass'
  | 'flood' | 'volcanicAsh' | 'pestSwarm' | 'wildfire' | 'bumperHarvest';
type EventKind = 'storm' | 'drought' | 'flare' | 'comet' | 'flood' | 'quake' | 'blight' | 'fire' | 'bounty';
interface MonthEvent {
  key: EventKey; kind: EventKind;           // one animation per kind; several keys share one
  title: string;                            // 2-4 words, e.g. "Dust storm"
  line: string;                             // one plain sentence of the effect
  scope: 'colony' | 'local' | 'personal';
  origin: { x: number; y: number };         // where the animation starts (edge point for colony)
  direction?: 'n' | 'e' | 's' | 'w';        // colony sweeps: the edge it comes in from
  plots: { index: number; order: number; good: Good; delta: number }[];
  player?: string;                          // personal events: whose land it started on
  sign: 'good' | 'bad' | 'mixed';
  when: 'afterProduction';
}
interface EventWarning { key: EventKey; title: string; line: string; arrivesMonth: number; visibility: 'public' | 'observatory' }
interface ProductionLine {
  tile: number; good: Good; made: number;
  parts: { why: 'ground' | 'trait' | 'species' | 'cluster' | 'pollution' | 'floor' | 'noEnergy' | 'noWater' | 'event' | 'factory';
           delta: number; event?: EventKey }[];
}
// MonthReport += { events: MonthEvent[]; warnings: EventWarning[]; lines: ProductionLine[] }
// GameState += { whatIf?: true }
```

Worked example: a dust storm from the west in month 4 hits ai1's Energy plot at index 37 (making 5 → 2) first and ai0's
at index 52 (4 → 2) second: `events[0] = { key: 'dustStorm', kind: 'storm', title: 'Dust storm', line: 'A dust storm
halves every Energy plot.', scope: 'colony', origin: { x: 0, y: 3 }, direction: 'w', plots: [{ index: 37, order: 0,
good: 'energy', delta: -3 }, { index: 52, order: 1, good: 'energy', delta: -2 }], sign: 'bad', when: 'afterProduction'
}`. `warnings` is always `[]` in this spec. Non-plot effects (WS6's item 4) are not produced by any event here.

## §4 · Failure & Ops `[handoff]`

No external dependency: events are in-process and deterministic.

| Question | Answer |
|---|---|
| A dependency unavailable? | None. |
| Retry / poison / page? | Not applicable: no I/O. |
| Idempotency? | A month's event is a pure function of the state at production; replay gives the same. |
| What can race? | Nothing: production is one synchronous step. |
| What works when events break? | `EVENTS.chance = 0` turns them off; the game is today's (HC-3). |
| How does an operator know? | The month report; `pnpm sim` prints events per month (T-AC-8). |

## §5 · Delivery `[handoff]`

Code-only; no existing state to reach. A game in progress on a server gains events from its next production; old month
reports simply lack the new fields (readers treat absent as empty).

## §7 · Risks & Spikes `[review-only]`

- **Balance moves.** Events add variance; the hunger and Food-spike checks are the likeliest to move. Mitigation: B-AC-1's
  rule (no ok → MISS on the same maps), tuning only EVENTS numbers, rows on both seed sets for Heiko (HC-6).
- **WS5's maps are pending.** Rows taken now move again on new maps. Mitigation: build and test now; take the HC-6 rows
  on the maps that are current when the PR opens, and re-take them in WS1's rebalance after WS5.
- **Per-plot lines grow the history.** About 40-80 lines a month over 12 months. Mitigation: plain numbers only; measure
  `JSON.stringify(state).length` before and after in the PR.
- **Production order.** A dust storm halving Energy plots also starves other plots of Energy this month, because Energy
  plots run first. That is intended (the catalogue's cascade), and RULE-4's noEnergy part shows it.
- No spike needed.
